The public source change extends the continuation validation from expected CCB
offset inequality alone to the logical OR of:

  continuation offset != current CCB expected offset
  current recomputed result count < continuation offset

and returns the invalid-continuation-state error before computing remaining
handles as result count minus continuation offset. The historical comparative
source at work/online-bluetooth-sdp-20261105/
sdp_server-android-4.4.4_r2.c has the expected-offset-only form. The patch and
source are comparative public evidence; neither proves target genealogy or a
direct upstream cherry-pick.

VBtd-51 INSTRUCTION EFFECTS

Result-count binding:
  0x841ade initializes the successful-result loop index in R15D to zero.
  0x841b09 copies the current loop index to EBP before each database call.
  A successful call reaches 0x841af2, which sets EBP to R15D + 1, then the
  successful handle is stored and R15 is incremented. Loop exit therefore
  leaves BP equal to the count of successfully stored current results. The
  zero-maximum route at 0x841db2 explicitly zeros EBP. This is positive operand
  binding, not an inference from a recovered variable name.

Continuation-offset binding:
  0x841b36 loads the first continuation-offset octet into R13D.
  0x841b3b copies it to EAX.
  0x841b3e loads the second octet into R13D.
  0x841b43 shifts the first value left by eight.
  0x841b46 adds it to R13D.
  Thus R13W is the parsed 16-bit continuation offset.

Independent checks and branch polarity:
  0x841b4d loads the zero-extended 16-bit CCB field at +0xb6 into ECX.
  0x841b54: cmpw %bp, %r13w
  0x841b58: ja 0x841bb0

In AT&T operand order, cmp source,destination computes destination minus source.
The compare therefore sets flags for unsigned R13W - BP. JA requires CF=0 and
ZF=0, so it branches exactly when unsigned continuation offset is greater than
unsigned current result count. Equality sets ZF and does not branch.

  0x841b5a: cmpw %cx, %r13w
  0x841b5e: jne 0x841bb0

This separate compare branches when the parsed continuation offset differs
from the current CCB expected offset. Result-count bounding and expected-offset
matching are different predicates; satisfying one does not imply the other.

Shared error and dominated subtraction:
  0x841bb0 begins the shared invalid-continuation-state route.
  0x841bb7 loads error code 5.
  0x841bc0 calls sdpu_build_n_send_error.
  That route exits and has no edge to the subtraction or handle-copy loop.

Only fallthrough from both checks reaches:
  0x841b60: movl %ebp, %ebx
  0x841b65: subl %r13d, %ebx

Consequently EBX receives current result count minus continuation offset only
after both checks accept. Both branches dominate this continuation-path
subtraction.

Later handle indexing:
  Accepted control reaches the response-count calculation at 0x841c09.
  0x841c1b compares the available response capacity with BX and either retains
  or caps the current count. At 0x841c9c the accepted continuation offset is
  copied to ECX; 0x841ca4 adds the selected count to form the loop end. The
  loop-entry comparison at 0x841cbd-0x841cc0 skips the body when start equals
  end. Only the body at 0x841cc8 reads a handle using ECX as the index.

There is no continuation-path edge from either code-5 error branch to that
read. Both independent checks therefore dominate later continuation handle
indexing as well as subtraction. If continuation offset equals current result
count, the unsigned bound accepts, subtraction yields zero, start equals end,
and 0x841cc8 is skipped. Equality is safe for the named underflow mechanism.

VBTD-63 INSTRUCTION EFFECTS

The second complete FDE has the same independent effects:

Result-count binding:
  0x8422ce initializes R15D; 0x8422f9 copies the pre-call index to EBP;
  0x8422e2 sets EBP to R15D + 1 on a successful result before the store and
  increment; 0x84259a explicitly handles zero maximum. BP is the successful
  current result count.

Continuation-offset binding:
  0x842326-0x842336 assembles the two parsed values into R13W using the same
  load/copy/load/left-shift/add sequence.

Independent checks and branch polarity:
  0x84233d loads the CCB +0xb6 expected offset into ECX.
  0x842344: cmpw %bp, %r13w
  0x842348: ja 0x8423a0
  This unsigned JA rejects exactly R13W > BP; equality is not taken.
  0x84234a: cmpw %cx, %r13w
  0x84234e: jne 0x8423a0
  This separately rejects expected-offset mismatch.

Shared error and dominated subtraction:
  0x8423a0 begins the shared error route; 0x8423a7 loads code 5 and
  0x8423b0 calls sdpu_build_n_send_error. Only dual-check fallthrough reaches
  0x842350 (EBX = EBP) and 0x842355 (EBX -= R13D).

Later handle indexing:
  Accepted continuation control reaches the count/cap logic at 0x8423f9.
  0x842480 loads the accepted offset as the start index; 0x842488 forms the
  end from offset plus selected count; 0x8424a1-0x8424a4 skips an empty range;
  only 0x8424b0 reads a handle by that index. The code-5 route has no edge to
  it. Both checks dominate the continuation-path read. Equality produces zero
  remaining handles and skips 0x8424b0.

BOUNDED CONCLUSION

Both exact FDEs contain the public fix's decisive instruction effect: unsigned
continuation offset greater than the current recomputed successful-result count
routes to the same code-5 continuation-state error used by expected-offset
mismatch, before subtraction. The current CCB expected-offset equality check is
also present and independent. Dual-check acceptance dominates subtraction and
later handle indexing. Equality is accepted by the bound, yields zero remaining,
and skips indexing.

Therefore the named CVE-2017-0785 continuation-offset unsigned-underflow /
out-of-bounds information-disclosure mechanism is rejected for these two exact
functions. This is direct fix-shaped behavior, not proof that either binary is a
direct cherry-pick of the public commit.

SDP code exists and the recovered vbtd.service is configured, but those facts
do not establish installed binary identity, process startup, SDP registration,
remote handler/channel reachability, adapter state, discoverability,
pairing/authentication/authorization policy, or preservation of any malformed
input. No disclosure or dynamic impact was attempted or observed.
