Write-bound matrix and caller effects
-------------------------------------
These conditional bounds hold independently for both exact binaries and both
handlers after syntactically valid input reaches ordinary response-list
construction and scratch allocation/reuse succeeds. Continuation additionally
requires accepted valid internal continuation state, including a feasible
attribute offset. Earlier error exits are outside the matrix. "Extent" is the
highest possibly written scratch offset plus one; it is not a claim that every
byte in that extent is written. "Maximum" means the effective internal maximum
after the remote-MTU cap, not unconditionally the peer-requested value.

  state          effective maximum  scratch extent upper bound  logical effective limit exceeded  64-byte capacity exceeded
  initial        0        3                           yes                     no
  initial        1        3                           yes                     no
  initial        2        3                           yes                     no
  initial        3        3                           no                      no
  continuation   0        0                           no                      no
  continuation   1        1                           no                      no
  continuation   2        2                           no                      no
  continuation   3        3                           no                      no

On the feasible initial response-building path, the outer sequence header can
reach offset 2, so an effective maximum below three is logically exceeded on
that path. For effective maxima 0..3, the initial cursor begins at +3 and the
first remaining-space tests prevent body construction before the header is
finalized. For accepted valid continuation state, the cursor begins at the
scratch base; whole builders use checked remaining space, and the complete
partial helpers clamp both copy length and destination advancement to
`min(remaining, total_serialized_length - attr_offset)` for a valid feasible
offset. The search-attribute handler additionally requires three remaining
bytes before reserving an inner sequence header. Continuation does not re-enter
outer initial-header construction. The resulting response copy length is at
most three for initial state and at most the effective maximum for continuation
state (vbtd-51 copy calls 0x84223c and 0x842b97; vbtd-63 copy calls 0x842a20 and
0x84335b). Existing successor routing then continues through the ordinary
response-buffer path; it does not add a write to the scratch allocation.

Under an ordinary protocol-valid remote MTU, a peer-requested small maximum
0..3 maps to the same effective internal value. The low/invalid remote-MTU
subtraction/wrap edge is not classified here.

The scratch allocation is not the public fix's max_list_len-sized allocation:
it is requested from remote MTU. On success, GKI chooses a pool with capacity
at least the request, and the smallest public user capacity is exactly 64
bytes. On failure, the returned null value is checked before scratch writes.
Every proven effective-small-maximum scratch extent on the stated feasible
path is therefore at most 3 within at least 64 user bytes.

Bounded conclusion
------------------
The source-like max_list_len < 4 guard is absent. On the feasible initial
response-building path, effective maxima 0..2 can reach scratch offset 2 and
therefore exceed the logical effective limit. Nevertheless, the
allocator/caller architecture in both exact binaries prevents that fact from
becoming the public small-maximum physical out-of-bounds write: the scratch
object is not sized to the small maximum and every successful object has at
least 64 user bytes. This conditionally rejects only the public physical
mechanism for CVE-2017-13255 and CVE-2017-13256 in the two hash-bound binaries.

This excerpt does not establish installed runtime identity, handler
reachability, adapter policy, channel security, owner-device applicability,
controlled behavior, memory corruption, code execution, unrestricted root,
persistence, early-error-path behavior beyond the stated exits, low/invalid
negotiated-MTU subtraction behavior, corrupted/impossible internal attribute-
offset safety, general partial-helper safety, allocator-corruption absence,
absence of every vendor-equivalent unnamed path, general SDP safety, or safety
of other SDP handlers.
