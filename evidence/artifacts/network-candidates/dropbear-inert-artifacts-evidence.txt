Unit semantics if all missing dependencies were restored
---------------------------------------------------------
ConditionPathExists=/tmp/secure_console_disable
Environment="DROPBEAR_RSAKEY_DIR=/var/dropbear"
EnvironmentFile=-/etc/default/dropbear
ExecStartPre=-/etc/dropbear/dropbear_publickey_installer.sh
ExecStart=-/usr/sbin/dropbear -i -s -r ${DROPBEAR_RSAKEY_DIR}/dropbear_rsa_host_key $DROPBEAR_EXTRA_ARGS
StandardInput=socket

`-i` is per-connection inetd/socket mode. `-s` disables password login. The
shipped default file comments out `-w`, so the static command does not disable
root login. The pre-start script copies the shipped public key into
`/home/root/.ssh/authorized_keys`, replacing a differing file. This would be a
root public-key authentication route only for a holder of the matching private
key and only if the server and socket path existed.

Marker and policy boundary
--------------------------
`/lib/systemd/esinit` creates `/tmp/secure_console_disable` by default and
removes it only when the MICOM secure_console parameter is 1. Thus the unit's
path condition is not the present blocker in the default no-secure-console
branch; the absent executable, socket unit, host-key unit/key, and enablement
are.

No explicit Dropbear SMACK rule or process-label assignment was found in the
reviewed recovered policy. With no executable/process, no runtime label can be
established.

Conclusion
----------
The recovered build contains stale or deliberately dormant Dropbear package and
configuration artifacts, including a root authorized public key, but no
executable or socket activation chain. A bounded search under recovered `mango-rootfs` found no candidate private-key
material using filename patterns `*.pem`, `*private*key*`, `id_rsa`, and
`id_ed25519`, or PEM markers `BEGIN [RSA|OPENSSH|EC] PRIVATE KEY`; this public
key was the only ordinary `ssh-rsa` occurrence. No cryptographic comparison was
possible without a candidate. This does not establish a listening
SSH service, accepted login, private-key possession, remote entry path, or CVE
exposure. A public key is not usable without possession of its private key.
