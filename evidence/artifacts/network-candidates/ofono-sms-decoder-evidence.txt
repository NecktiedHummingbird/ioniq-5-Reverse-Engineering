Exact authentic QMI-to-parser route
----------------------------------
All addresses are file virtual addresses in the PIE.

The vendor `lgeqmimodem` SMS region contains the nearby source/log identities
`raw_read_cb`, `event_notify`, `QMI_WMS_RAW_READ`, "3GPP Message with
Indication", "ack_required ... transaction id", and "PDU length".

Direct indication/transfer path at 0x4a8cb..0x4a8d6:

  4a8cb: lea 0x8(%r13), %rsi       # QMI-provided PDU
  4a8cf: mov %ebx, %ecx            # TPDU length
  4a8d1: mov %ebx, %edx            # total length
  4a8d3: mov %rbp, %rdi            # struct ofono_sms *
  4a8d6: call 0xa5580               # ofono_sms_deliver_notify

Stored/raw-read path at 0x4a9d5..0x4a9e7:

  4a9d5: mov 0x8(%r13), %rsi        # QMI result PDU pointer
  4a9d9: mov %r14d, %ecx            # TPDU length
  4a9dc: mov %r12, %rdi             # struct ofono_sms *
  4a9df: movzbl (%rsi), %eax         # SMSC length octet
  4a9e2: lea 0x1(%r14,%rax), %edx   # total length
  4a9e7: call 0xa5580               # ofono_sms_deliver_notify

`ofono_sms_deliver_notify` allocates a 0x128-byte `struct sms` at `rsp+0x30`
and calls the internal decoder:

  a55d6: lea 0x30(%rsp), %rbp
  a55e3: mov %r14d, %ecx
  a55e6: mov %r12, %r8
  a55e9: mov %ebx, %esi
  a55eb: mov %rbp, %rdi
  a55ee: call 0xae8a0               # sms_decode

The handler then checks the decoded type at `sms+0x20` and continues normal
handling only for type 0 (`SMS_TYPE_DELIVER`). This check occurs after
`sms_decode` has completed. For `outgoing=FALSE`, its exact TP-MTI dispatch is:

  MTI 0 -> 0xae980 / deliver body 0xadca0
  MTI 1 -> 0xaeb30 / submit report
  MTI 2 -> 0xae998 / status report
  MTI 3 -> 0xae980 / treated as deliver

Thus status- and submit-report decoder writes precede the later type rejection.
The incoming route cannot select deliver-report or command decoding.

CVE-2023-4233: exact missing address bound
------------------------------------------
The address decoder begins at 0xada70. It reads the one-byte address length at
0xada99, advances the offset, reads the type octet, and calculates the
non-service-centre encoded length as `(addr_len + 1) >> 1` at
0xadadf..0xadae4. At 0xadae7..0xadaed it compares only that length with the
remaining source bytes. There is no rejection for `addr_len > 20` or
`byte_len > 10`.

For a non-alphanumeric address, destination `sms+0x3c` is selected at 0xadb28.
The loop at 0xadb48..0xadb70 writes two lookup bytes for each encoded source
byte. Instructions 0xadb72..0xadb78 then write a terminator at twice the
encoded length. The destination array is 23 bytes.

Exact one-byte input domain (assuming the separately checked source bytes are
present):

  addr_len 0..20: specification-bounded, 21 values
  addr_len 21..22: oversized but still 23-byte-array-bounded, 2 values
  addr_len 23..255: address-array overflow, 233 values
  addr_len 255: 128 encoded bytes -> 257 output bytes
  maximum array overrun: 234 bytes
  maximum write end: sms+0x13d
  maximum beyond the 0x128-byte sms object: 21 bytes

CVE-2023-2794: exact missing deliver-data bound
----------------------------------------------
The deliver decoder begins at 0xadca0 and calls the address decoder at 0xadd1c.
It stores UDL at `sms+0x68`, then calls the recovered `sms_udl_in_bytes` logic
at 0xad1c0:

  add95: mov %dil, 0x68(%rbx)
  add99: call 0xad1c0
  add9e: cmp %ebp, %eax
  adda0: jg 0xaddc0                 # source availability only
  adda2: lea 0x69(%rbx), %rdi       # 140-byte destination

  addb0: call memcpy@plt            # unfortified copy

Exact caller and hardening boundary
----------------------------------
In `ofono_sms_deliver_notify`, the sms object starts at caller `rsp+0x30`, a
later scratch object starts at `rsp+0x160` (`sms+0x130`), and the stack canary
is at `rsp+0x1f8` (`sms+0x1c8`). Neither reviewed maximum write directly
reaches the canary in this exact caller. Later code initializes the scratch
object on the reviewed path, but that does not make the earlier out-of-bounds
writes safe or prove that no corrupted object state is consumed.

ELF review:

  Type: DYN (PIE)
  GNU_STACK: RW (NX)
  GNU_RELRO present
  BIND_NOW present
  imports __stack_chk_fail
  imports both memcpy and __memcpy_chk

The vulnerable call at 0xaddb0 is `memcpy@plt`, not `__memcpy_chk`. These
mitigations do not prevent the two exact writes, but the writes alone do not
demonstrate controlled instruction-pointer corruption or code execution.

Service, uid, D-Bus, and SMACK boundary
---------------------------------------
`ofono.service` contains:

  ConditionPathExists=/tmp/telematics_code_TELEMATICS
  Type=dbus
  BusName=org.ofono
  ExecStart=/usr/sbin/ofonod -nd
  Restart=always

No `User=` is present, so systemd starts the service as uid 0. The executable
is assigned `security.SMACK64EXEC=App::tms` by `smack-relabel-ro.sh`. The tms
policy permits `_`, its own data/log labels, and many application labels, but
SMACK remains a mandatory boundary. This is not evidence of unrestricted root.

`ofono.path` requires both `/tmp/no_isa` and the telematics marker and names
`ofono.service`. No enabling symlink for `ofono.path` was found under the
recovered `multi-user.target.wants`. `mof.service` is enabled and has
`After=... ofono.service ...`, but `After=` orders units and does not pull in
the named service. A unit and conditional path therefore prove available
activation machinery, not observed owner-vehicle activation.

Claim boundary
--------------
The exact recovered binary retains all six reviewed pre-fix decoder conditions.
The authentic vendor QMI incoming route can select deliver, submit-report, and
status-report decoding before its late type check. Deliver-report and command
require outgoing/local transmit-queue or SIM-Toolkit decode routes. If this
service starts, it is uid 0 with the `App::tms` SMACK label.

Not established: the owner's installed binary, telematics/no-ISA marker state,
unit activation, modem attachment, QMI service state, carrier/base-station/SMS
preservation and delivery of malformed incoming TPDUs, malicious local queue
content, malformed SIM-Toolkit input, direct radio reachability of outgoing-only
decoders, dynamic process corruption or termination, controlled execution,
SMACK escape, persistence, or a root transition.
